# 한국 수요를 증거로 만드는 법

작성: 노드 · 2026-11-23 · 승리님 결정에 따른 후속
결정: **「한국 바이어 쪽은 자산이다. 유럽 브랜드가 입점할 이유는, 이 사이트를
통해 찾는 한국 고객 수가 많다는 걸 보여 주는 것이다.」**
**아직 아무것도 고치지 않았습니다.**

---

## 0. 왜 이것이 오늘 할 일인가

거짓 브랜드 수도, 카피도, 매거진 문도 **아무 날에나** 고칠 수 있습니다.
그런데 **「한국 고객이 이만큼 찾는다」는 증거는 소급해서 만들 수 없습니다.**
오늘 기록하지 않은 하루는 영구히 비어 있습니다.

그래서 순서가 이렇게 됩니다 — **먼저 기록을 켜고, 그다음에 보여 줄 것을 고칩니다.**

---

## 1. 지금 무엇이 기록되고 무엇이 버려지나 (실측)

### 기록되고 있는 것 — 생각보다 좋습니다

| 어디서 | 컬렉션 | 품목을 알 수 있나 | 묻는 사람을 알 수 있나 |
|---|---|---|---|
| 자재 소싱 문의 | `leads` | **`category` 있음** ✓ | `industry` ✓ |
| 브랜드 쪽 문의 | `leads` | `brandId`·`brandName` → 품목을 끌어올 수 있음 | `industry` ✓ |
| 제품 쪽 문의·견적 | `leads` | `productId`·`productName` → 같음 | `industry` ✓ |
| 컨설팅 요청 | `consultations` | 관심 분야 | ✓ |
| BIM·도면 요청 | `bim-requests` | 제품·프로젝트 | ✓ |
| 뉴스레터 | `newsletter-subscribers` | — | — |

**셋 다 `createdAt` 을 남깁니다.** 즉 **품목별 · 기간별 · 직군별 집계가 지금
당장 가능합니다.** 데이터 모형은 이미 맞습니다 — **집계하고 보여 주는 쪽이 없을 뿐입니다.**

★ `industry` 가 특히 값있습니다. 「문의 40건」보다 **「건축사 23명 · 인테리어
11명 · 딜러 6명이 물었습니다」**가 유럽 브랜드에게 훨씬 센 말입니다.
수(數)가 아니라 **누구**이기 때문입니다.

### 버려지고 있는 것 — 양으로는 이쪽이 훨씬 큽니다

| 무엇 | 지금 | 왜 아까운가 |
|---|---|---|
| **사이트 검색어** | `search.js` 가 **아무것도 기록하지 않습니다** | 한국 전문가가 **무엇을 찾는지 직접 타이핑한 것**입니다. 가장 순수한 수요 신호인데 매번 버려집니다 |
| **결과 0건 검색** | 기록 없음 | **가장 센 신호입니다.** 「한국 전문가가 찾았는데 우리에게 없다」 = 유럽 브랜드를 들여올 이유 그 자체 |
| 카테고리 조회 | GA4 기본 `page_view` 만 | 품목별 관심도를 못 가릅니다 |

문의는 **결심한 사람**만 남깁니다. 검색은 **둘러보는 사람 전부**가 남깁니다.
둘의 양 차이가 보통 수십 배입니다. 지금 우리는 작은 쪽만 받고 큰 쪽을 버립니다.

---

## 2. 이미 가진 것으로 만들 수 있는 것 — 승인도 규칙 변경도 필요 없음

**지금 기록 중인 `leads` 만으로** 아래 리포트가 나옵니다. 새 수집이 없으니
처리방침도 Firestore 규칙도 건드리지 않습니다.

```
  한국 수요 리포트 — 최근 90일
  ─────────────────────────────────────────
  문의 합계              N건
  품목별                조명 N · 마감재 N · 가구 N …
  묻는 사람             건축사 N · 인테리어 N · 딜러 N · 기타 N
  문의가 온 경로         소싱 쪽 N · 브랜드 쪽 N · 제품 쪽 N
  달별 추이             9월 N · 10월 N · 11월 N
```

**솔직히 적습니다 — 지금 이 숫자는 0에 가까울 겁니다.** 브랜드가 1개이고
사이트가 이제 막 정리됐으니 당연합니다. 그런데도 지금 만드는 이유는
**만들어 둬야 시계가 돌기 시작하기 때문**입니다. 석 달 뒤에 만들면
석 달치가 없습니다.

---

## 3. 버려지는 것을 줍는 법 — 두 단계, 사이에 법적 관문

검색어를 기록하는 것은 **사이트가 수집하는 개인정보의 범위를 바꾸는 일**입니다.
지금 처리방침 제3조의 「자동으로 생성·수집되는 정보」에는 접속 IP·쿠키·접속
일시·브라우저 정보만 적혀 있고 **검색어는 없습니다.** 그래서 두 단계로 나눕니다.

### 1단계 — 글자를 저장하지 않는다 (개인정보 쟁점이 거의 없음)

검색어 「무광 세라믹 타일 600각」을 **글자 그대로 저장하지 않고**, 맞춘
분류와 결과 수만 셉니다:

```
  { cat: 'finishes', sub: 'tiles-ceramics', hits: 0, ts: <시간 단위로 반올림> }
```

- 자유 입력 글자 **없음** · 사용자 식별자 **없음** · IP **없음**
- 시각은 **시간 단위로 반올림**(분·초를 남기면 사람을 되짚을 여지가 생깁니다)
- 이건 사람에 대한 기록이 아니라 **칸의 계수기**입니다

이걸로 「조명 카테고리를 90일간 N번 찾았다」가 나옵니다. 승리님이 말씀하신
**「찾는 한국 고객 수」**의 본체가 여기입니다.

### 2단계 — 결과 0건일 때만 글자를 남긴다 (처리방침 갱신 후)

0건 검색어는 **특정 브랜드를 들여올 근거**라서 글자가 필요합니다
(「세라믹 600각을 47명이 찾았는데 우리에게 없다」). 그런데 글자를 남기는
순간 수집 범위가 바뀝니다. **그래서 반드시 ㄱ)처리방침 제3조 갱신
ㄴ)변호사 검토 ㄷ)승리님 승인 뒤에 켭니다.** 제가 먼저 켜지 않습니다.

> 이건 제가 판단할 자리가 아닙니다. 저는 변호사가 아니고, 이미 A-539·A-583 이
> 변호사 검토 대기 중입니다. 같은 묶음에 올립니다.

## 4. 유럽 브랜드에게 보여 주는 화면

리포트는 **두 가지 판**이 필요합니다.

**ㄱ) 내부용 (어드민)** — 승리님이 보는 전체. 품목·직군·경로·추이 전부.

**ㄴ) 브랜드용 (영업 자료)** — 한 품목만, 한 장:

```
  조명 — 한국 수요 (최근 90일)
  ─────────────────────────────────────────
  이 카테고리를 찾은 횟수        N회
  그중 우리에게 없어서 빈손      M회     ← 2단계가 켜져야 나옵니다
  직접 문의한 사람              K명
    건축사 a · 인테리어 b · 딜러 c
  관련 기사를 읽은 횟수          P회
  ─────────────────────────────────────────
  ARCHINODE 는 이 수요를 매달 기록합니다.
```

**이 한 장이 「입점하세요」보다 셉니다.** 디렉터리는 수요를 꾸밀 수 있지만
이 기록은 꾸밀 수 없고, 꾸미지 않았다는 것이 이 장의 값입니다.

★ 그래서 **숫자가 작아도 그대로 보여 주는 쪽을 권합니다.** 작은 진짜 숫자가
큰 가짜 숫자보다 셉니다 — 지금 `categories.html` 의 2,910+ 가 바로 그
반대편 사례입니다.

## 5. 순서

| # | 무엇 | 승인 필요 | 드는 일 |
|---|---|---|---|
| 1 | **어드민 수요 리포트** — 지금 있는 `leads` 를 품목·직군·기간으로 집계 | 없음 | 하루 |
| 2 | **1단계 검색 신호** — 분류·결과수만 세는 계수기 + Firestore 규칙 + 공개쓰기 한도 | **규칙 발행 필요**(푸시로 안 됩니다) · 승리님 승인 | 하루 |
| 3 | **브랜드용 한 장** (§4-ㄴ) | 무엇을 공개할지 승리님 결정 | 반나절 |
| 4 | **2단계 0건 검색어** | **처리방침 갱신 + 변호사 + 승인** | 반나절 (관문 통과 후) |
| 5 | 카테고리 조회수 (GA4 사용자 정의 사건) | 승인 | 반나절 |

**1번은 지금 시작할 수 있습니다.** 새 수집이 없고 읽기만 하며,
어드민 화면 안에서만 돕니다.

## 6. 승리님이 정하셔야 하는 것

| 무엇 | 왜 |
|---|---|
| 2번(검색 계수기)을 켤지 | 새 컬렉션 + 공개 쓰기입니다. Firestore 규칙은 **따로 발행**해야 켜집니다 |
| 브랜드에게 **무엇까지** 보여 줄지 (§4-ㄴ) | 0건 수치는 우리 약점이기도 합니다. 저는 **보여 주는 쪽**을 권합니다 — 그게 들여올 이유니까요 |
| 숫자가 작을 때도 보여 줄지 | 저는 **그대로 보여 주자**는 쪽입니다 |
| 4번(0건 검색어 글자)을 추진할지 | 변호사 묶음(A-539·A-583)에 함께 올릴지 |
| 리포트 기간을 90일로 할지 | 짧으면 숫자가 작고, 길면 최신성이 떨어집니다 |

## 7. 한 문장으로

> 그 기록은 오늘부터 쌓아야 하고, 작아도 진짜여야 한다.**
