# ARCHINODE 검수 대장

발견한 결함·개선점을 **전부 여기에 쌓는다.** 보고서(`archi-diary/bronze-*.md`)는 그날의 기록이고, "지금 무엇이 열려 있나"는 이 대장이 정본이다.
**2026-09-12부터 새 등록은 어드민 > 「검수관리」 탭(`reviewIssues`)에 한다** (한울님 "A절로 옮겨서 빨리 만들어"). 이 파일의 A-001~A-010은 탭의 [문서 대장 10건 가져오기]로 이관하고, 그 뒤 이 파일은 이관 전 기록으로만 남긴다. 탭이 라이브에 나가고 규칙이 게시되기 전까지는 임시로 여기에 계속 적는다.

## 규칙 (단번 검수판 · 엑사 검수관리 게시판을 문서로 축약)

- **등록은 누구나(브론즈·블랙·지휘 창·한울님), 판정은 사람만.** 에이전트가 올린 건은 `검토대기`로 들어가고, 한울님(또는 한울님이 위임한 지휘 창)이 「진짜 문제」로 올려야 수정 대상이 된다. 아무리 명백해 보여도 이 단계를 건너뛰지 않는다.
- **상태 순환**: `검토대기` → `진행중` / `보류` / `오탐반려` → (수정 뒤) `확인대기` → `확인완료` / `재수정요청`. 상태가 바뀌면 **이력 칸에 한 줄** 추가(날짜·누가·무엇).
- **네 칸(눌렀나·기대·실제·문제)은 비개발자가 읽는 글이다.** 파일 이름·줄 번호·콘솔 원문·함수명은 **개발 메모** 칸에만.
- 우선순위: **High**(방문자·브랜드가 겪는다) / **Medium**(운영이 겪는다, 또는 보안) / **Low**(콘솔·문구·정리).
- 번호는 `A-###`, 재사용 금지. 중복 발견이면 새 번호를 만들지 말고 기존 건 이력에 "재발견"을 적는다.
- 브론즈 보고 형식의 「검수대장 등록: 번호 목록」이 이 파일과 짝이다.
