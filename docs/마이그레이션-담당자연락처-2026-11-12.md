# 담당자 연락처 옮기기 (A-480) — 1회성

**왜:** 승인된 `brands` 문서는 규칙상 **문서 전체가 공개 읽기**다. 화면에 안 그려도
질의 한 번으로 전 브랜드 담당자의 이름·직함·이메일·전화·유입경로가 수집됐다.
Firestore 규칙에는 필드 단위 읽기가 없어서, 항목을 **옮기는 것** 말고는 막을 방법이 없다.

**새 자리:** `brands/{id}/internal/contact` — 어드민과 그 브랜드 본인만 읽는다.

**코드는 이미 양쪽을 본다.** 병합은 「본문서 → contact 로 덮기」 순서라서,
아직 안 옮긴 문서도 전과 똑같이 보인다. 그래서 **푸시와 마이그레이션의 순서는 상관없다.**
다만 규칙은 먼저 게시돼야 한다(아래 0단계).

## 0단계 — 규칙 게시 (필수, 먼저)

Firebase 콘솔 → Firestore → 규칙 → `firestore.rules` 내용 붙여넣고 **게시**.
`git push` 는 규칙을 게시하지 않는다. 게시 전에는 `internal/contact` 쓰기가 전부 거부된다.

## 1단계 — 콘솔에서 1회 실행

1. `https://archinodekr.com/admin/dashboard.html` 에 **어드민으로 로그인**한 상태로 연다.
2. F12 → Console.
3. 아래를 통째로 붙여넣고 Enter.

```js
(async () => {
  const F = ['contactName','position','email','phone',
             'referral','referralSource','agreedVendorTerms','agreedVendorTermsAt'];
  const snap = await db.collection('brands').get();
  const log = [];
  for (const d of snap.docs) {
    const data = d.data() || {};
    const pick = {};
    F.forEach(k => { if (data[k] !== undefined) pick[k] = data[k]; });
    const keys = Object.keys(pick);
    if (!keys.length) { log.push({ id: d.id, brand: data.brandName || '', 결과: '옮길 것 없음' }); continue; }
    // 1) 먼저 옮겨 심는다
    await d.ref.collection('internal').doc('contact').set(pick, { merge: true });
    // 2) 되읽어 확인한 다음에만 본문서에서 지운다 (확인 안 되면 본문서를 건드리지 않는다)
    const chk = await d.ref.collection('internal').doc('contact').get();
    const ok = chk.exists && keys.every(k => chk.data()[k] !== undefined);
    if (!ok) { log.push({ id: d.id, brand: data.brandName || '', 결과: '★중단 — 옮긴 값 확인 실패, 본문서 그대로' }); continue; }
    const del = {};
    keys.forEach(k => { del[k] = firebase.firestore.FieldValue.delete(); });
    await d.ref.update(del);
    log.push({ id: d.id, brand: data.brandName || '', 결과: '옮김: ' + keys.join(', ') });
  }
  console.table(log);
  console.log('끝. 「★중단」 이 있으면 노드에게 그 줄을 알려 주세요.');
})();
```

- `db` · `firebase` 는 그 페이지의 전역이라 콘솔에서 그냥 쓰인다(상단 프레임에서 실행할 것).
- **지우기 전 내용의 기록**은 `internal/contact` 자체다 — 먼저 심고, 되읽어 확인한 뒤에만 지운다.
  값을 콘솔에 찍지 않는 이유도 같다(개인정보를 로그에 남기지 않는다).
- 한 번 더 실행해도 안전하다(이미 옮긴 문서는 「옮길 것 없음」).

## 2단계 — 확인

1. 어드민 → 브랜드 표에 담당자 이름이 **그대로 보이는지** (병합이 도는지).
2. 브랜드 상세 모달의 Contact / Email / Phone / Referral.
3. 브랜드 포털 → 연락처 탭에 값이 보이고, 저장이 되는지. (노드는 로그인할 수 없어 못 본다.)
4. 로그아웃 상태에서 콘솔:
   `(await firebase.firestore().collection('brands').where('status','==','approved').get()).docs.map(d=>Object.keys(d.data()).filter(k=>['email','phone','contactName'].includes(k)))`
   → 전부 빈 배열이어야 한다.
