# 자료 파일 URL 옮기기 (A-483) — 1회성

**왜:** 카탈로그 PDF·BIM·3D 모델의 **다운로드 URL** 이 공개 제품 문서
(`catalogPdf`·`bimFile`·`model3d`)에 있었다. 승인된 제품 문서는 **문서 전체가 공개 읽기**라,
「로그인 → 신청 → 어드민 승인 → 7일 링크」 절차가 **아무것도 막지 못했다** —
제품 JSON 한 번이면 URL 이 그대로 나왔다.

**새 자리:** `products/{id}/internal/files` — 어드민과 소유 브랜드만.
공개 문서에는 **있는지 여부**만 둔다(`hasCatalogPdf` · `hasBimFile` · `hasModel3d`).

**Storage 도 함께 닫았다:** `products-specs` 가 `allow read: if true` 였다.
`read` 는 **목록(list)까지** 허용하므로 `listAll('products-specs')` 로 전 브랜드 자료 파일을
훑어 받아갈 수 있었다. 이제 본인과 어드민만.
※ 승인된 신청자에게 **이미 메일로 간 7일 링크는 그대로 열린다** — `getDownloadURL()` 의
토큰 URL 은 규칙을 타지 않는다(토큰 자체가 권한이다). 막은 것은 **경로 훑기**다.

**순서:** ① Firestore 규칙 게시 ② Storage 규칙 게시 ③ 아래 1회 실행.

## 콘솔에서 1회 실행 (어드민으로 로그인한 `/admin/dashboard.html` 에서)

```js
(async () => {
  const F = ['catalogPdf', 'bimFile', 'model3d'];
  const HAS = { catalogPdf: 'hasCatalogPdf', bimFile: 'hasBimFile', model3d: 'hasModel3d' };
  const snap = await db.collection('products').get();
  const log = [];
  for (const d of snap.docs) {
    const x = d.data() || {};
    const pick = {}, flags = {}, del = {};
    F.forEach(k => {
      const v = x[k];
      if (typeof v === 'string' && v) pick[k] = v;
      flags[HAS[k]] = !!(x[HAS[k]] || (typeof v === 'string' && v));
      if (Object.prototype.hasOwnProperty.call(x, k)) del[k] = firebase.firestore.FieldValue.delete();
    });
    if (!Object.keys(pick).length && !Object.keys(del).length) {
      log.push({ id: d.id, name: x.name || '', 결과: '옮길 것 없음' }); continue;
    }
    // 1) 먼저 옮겨 심는다
    if (Object.keys(pick).length) {
      await d.ref.collection('internal').doc('files').set(pick, { merge: true });
      // 2) 되읽어 확인한 뒤에만 공개 문서에서 지운다
      const c = await d.ref.collection('internal').doc('files').get();
      const got = c.exists ? (c.data() || {}) : {};
      const ok = Object.keys(pick).every(k => got[k] === pick[k]);
      if (!ok) { log.push({ id: d.id, name: x.name || '', 결과: '★중단 — 확인 실패, 공개 문서 그대로' }); continue; }
    }
    await d.ref.update(Object.assign({}, flags, del));
    log.push({ id: d.id, name: x.name || '', 결과: '옮김: ' + (Object.keys(pick).join(', ') || '(URL 없음, 여부만 설정)') });
  }
  console.table(log);
  console.log('끝. 「★중단」 이 있으면 노드에게 그 줄을 알려 주세요.');
})();
```

- 한 번 더 실행해도 안전하다.
- 공개 문서의 `hasX` 는 **URL 이 없던 제품에도** false 로 채워진다(단추 판정이 한결같아진다).

## 확인

1. 공개 제품 페이지: 자료 단추(PDF·BIM·3D)가 **전과 같이** 뜨는지.
2. 로그아웃 상태 콘솔에서 승인된 제품 문서를 읽어 `catalogPdf`·`bimFile`·`model3d` 가 **없는지**.
3. 어드민 → 제품 상세: 파일 링크 3개가 전과 같이 보이는지.
4. 어드민 → BIM/CAD 신청 승인: 메일의 다운로드 링크가 열리는지(제가 로그인할 수 없어 못 봤습니다).
5. 브랜드 포털 → 제품 **수정**: 파일을 새로 고르지 않고 저장해도 단추가 그대로 남는지.
6. 로그아웃 상태 콘솔에서 `firebase.storage().ref('products-specs').listAll()` → **거부**되는지.
