- **낸 사람**: 지휘 창 (26.09.12 아키노드 #1)
- **하는 사람**: node-white (지휘 창이 Agent 도구로 직접 호출 — 한울님 "빨리 만들어" 지시라 실행창 개설 생략)

## 배경

브론즈·블랙이 결함을 찾으면 지금은 `docs/검수대장.md`(마크다운 표)에 줄을 추가한다. 한울님은 파일을 열어야 볼 수 있고 상태 변경도 손으로 한다. 단번(THE BIDDING)은 이것을 어드민 화면 안 게시판으로 만들었고, 엑사(EX Works)는 9월 8일에 `bronzeIssues` 컬렉션 + 회사관리 탭으로 축약 이식했다. 한울님이 9월 12일에 "A절로 옮겨서 빨리 만들어"라고 했다. **정식 오픈 전까지 쓰는 임시 도구다 — 과설계 금지.**

## 고칠 것

### 1. 새 컬렉션 `reviewIssues` (문서 필드)

```
no          "A-011" 형식 문자열. 등록 시 컬렉션 안 최대 번호 +1 (기존 문서 대장이 A-010까지 쓰므로 A-011부터)
area        메뉴·영역 (자유 텍스트, 예: "홈", "어드민", "브랜드 포털", "입점 신청")
screen      화면·경로 (예: "index.html", "admin/dashboard.html 브랜드 탭")
action      무엇을 눌렀나        ┐
expectation 무엇을 기대했나      │ 이 네 칸은 비개발자(한울님)가 읽는 글 — 파일명·줄번호·콘솔 원문·함수명 금지
current     실제로 뭐가 보였나   │
gap         그래서 뭐가 문제인가 ┘
priority    "High" | "Medium" | "Low"
status      "검토대기"(기본) → "진행중" | "보류" | "오탐반려" → "확인대기" → "확인완료" | "재수정요청"
techNote    기술 근거 (파일:줄, 콘솔 원문 등). 상세에서 기본 접힘
pageUrl     재현 주소 (선택)
reportedBy  등록자 (어드민이 화면에서 등록하면 로그인 이메일, 브론즈가 등록하면 "노드-브론즈")
reportedAt  등록 시각 (serverTimestamp)
updatedAt   마지막 변경 시각
history     [{status, by, at(ISO 문자열), note}] — 상태가 바뀔 때마다 한 줄 추가. 등록 시 첫 줄 {status:"검토대기", by, note:"등록"}
```

### 3. 화면 — `admin/dashboard.html` (651줄. **큰 파일 취급 — Edit 도구로 통째 치환 금지, Node 줄 단위 삽입.** 끝나면 `</html>` 확인)

기존 패턴을 그대로 따른다: `.tabs`의 `.tab`(153~155줄) · `.tab-content`(159/179/199줄) · `.section-card` 표 · `#modal`/`#modalContent`(219~223줄) · `escapeHtml()`(537줄) · `loadAll()`(245줄) · 탭 전환 스크립트(627줄대) · 인라인 `<style>`(20~102줄). **새 스타일은 기존 클래스 재사용, 색은 흑백회색 + 골드 `#C8A96E`, 상태 뱃지는 기존 `.status` 패턴.** 모든 라벨은 `data-en`/`data-ko` 짝.

3-1. 탭: `<div class="tab" data-tab="review" data-en="Review Board" data-ko="검수관리">Review Board <span class="count" id="reviewCount"></span></div>` — 배지 숫자는 `검토대기` 건수(기존 탭들이 pending 수를 쓰는 것과 동일).

3-2. `#tab-review` 안 `.section-card`:
- 상단 한 줄: 상태 필터 `<select id="reviewFilter">` — 「열린 것만(기본: 확인완료·오탐반려 제외)」/「전체」/각 상태 7개. 우선순위 필터는 만들지 마라(과설계).
- 오른쪽 `[+ 등록]` 버튼(`.act-btn`), 그리고 **`[문서 대장 10건 가져오기]`** 버튼 — 컬렉션이 비어 있을 때만 보인다(아래 3-5).
- 표: 번호 · 화면(area / screen) · 문제(gap, 60자 넘으면 말줄임) · 우선(High 빨강·Medium 골드·Low 회색 뱃지) · 상태 뱃지 · 등록일 · 등록자 · 작업 `[보기]`.
- 정렬: 상태가 `검토대기`·`재수정요청`·`확인대기` 우선, 그 안에서 High → Medium → Low, 그 다음 최신순. **컬렉션이 작으니 클라이언트에서 정렬** — 복합 색인 만들지 마라.

3-3. `[+ 등록]` → 기존 `#modal`에 폼: area, screen, action, expectation, current, gap(textarea), priority(select, 기본 Medium), techNote(textarea, 라벨에 "개발 메모 — 기술 용어는 여기에만"), pageUrl. 저장 → `no` 자동 발번 → `history` 첫 줄 → 목록 재로드. **`window.confirm`/`prompt` 쓰지 마라** — 단번·엑사 둘 다 이것 때문에 자동 검증이 막혔다. 필수 칸 비면 폼 안에 빨간 문구.

3-4. `[보기]` → 모달 상세: 번호·우선·상태 헤더, 4단(눌렀나/기대/실제/문제) 정의목록, `pageUrl` 있으면 링크(`target=_blank rel=noopener`, `javascript:` 차단 — 기존 website 가드와 같은 방식), techNote는 `<details>`로 접힘, history 타임라인(최신 위), 아래에 **상태 변경 `<select>` + 메모 `<input>` + `[상태 저장]`** → `status`·`updatedAt` 갱신 + `history`에 `{status, by: 로그인 이메일, at, note}` push. 확인창 없음.

3-5. `[문서 대장 10건 가져오기]`: 페이지 안에 아래 10건을 JS 배열로 내장하고, 클릭 시 컬렉션이 비어 있는지 다시 확인한 뒤 batch로 넣는다(`reportedBy: "문서 대장 이관"`, 각 `history` 첫 줄 note "docs/검수대장.md에서 이관"). 데이터 원본은 `docs/검수대장.md`의 A-001~A-010 표 — **네 칸·우선·상태·개발 메모·이력 문장을 그 표에서 그대로 옮겨라.** 등록일은 표의 등록일을 `reportedAt`이 아니라 history note에 적고, `reportedAt`은 serverTimestamp. 가져온 뒤 버튼은 숨긴다.

3-6. `loadAll()`에 `loadReview()` 추가. 모든 `${...}` 출력은 `escapeHtml`.

## 검증

- **node-black 검수 필수** — 지휘 창이 이어서 호출한다. 화이트는 스스로 `node --check`(인라인 스크립트 추출) + `tail -3 admin/dashboard.html`에 `</html>` + 줄 수가 HEAD 대비 줄지 않았는지 확인해 보고에 적는다.
- 로그인이 필요한 실측(등록→상태변경→가져오기)은 **어드민 비밀번호가 없어 못 한다.** "확인 못 함"으로 적고, 대신 로컬에서 페이지를 열어 문법 오류·탭 전환·모달 열림(비로그인 리다이렉트 전 단계까지)만 확인한다.
