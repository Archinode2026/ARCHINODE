## 배경 (처음 보는 사람용)

사이트의 핵심은 "가격 문의·브랜드 문의·딜러 연결"이 브랜드에게 **리드**로 전달되는 것인데(규정집 1-1·1-3), 지금은 그 문의가 Formspree 메일로 한울님 받은편지함에만 도착하고 브랜드는 아무것도 못 본다. 규칙 파일에 `leads`가 선언만 돼 있고 쓰는 곳이 없다. 4a는 어드민이 리드를 등록·배정·추적하는 인박스와, 브랜드 포털에서 배정된 리드를 보는 Inbox 탭을 만든다. 공개 페이지의 문의 버튼을 리드 폼으로 바꾸는 것(4b)은 한울님 복귀 후.

## 고칠 것

### 1. `firestore.rules` — `leads` 블록 교체 (현재 167~180줄대, 실제 위치는 파일에서 확인)
```
    match /leads/{leadId} {
      // 생성: 누구나(4b 공개 폼 대비) — 필수 필드·type·status=='new'·createdAt==request.time
      allow create: if request.resource.data.type in ['quote','brand-inquiry','dealer']
                    && request.resource.data.status == 'new'
                    && request.resource.data.name is string && request.resource.data.name.size() > 0
                    && request.resource.data.email is string && request.resource.data.email.size() > 5
                    && request.resource.data.message is string
                    && request.resource.data.createdAt == request.time;
      // 읽기: 어드민, 또는 배정된 브랜드 본인
      allow read: if isAdmin() || (isSignedIn() && resource.data.brandId == request.auth.uid);
      // 수정: 어드민 전부 / 브랜드는 배정 건에서 status·brandNote·history·updatedAt 만
      allow update: if isAdmin()
                    || (isSignedIn() && resource.data.brandId == request.auth.uid
                        && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['status','brandNote','history','updatedAt'])
                        && request.resource.data.status in ['assigned','contacted','closed']);
      allow delete: if isAdmin();
    }
```
기존 블록의 조건 중 위와 다른 것이 있으면(예: 필수 필드 이름) **기존 규칙 파일의 실제 조건을 읽고 맞춰라** — 필드 이름은 계약서 4-3이 정본. `list` 쿼리는 규칙이 문서별로 판정하므로 브랜드 포털은 반드시 `where('brandId','==',uid)`로만 조회(아니면 전체 거부).

### 2. `admin/js/view-leads.js` (신규, ~350줄) — 고객 > 「리드 인박스」
- 목록: `orderBy('createdAt','desc').limit(200)` + 「더 보기」. 필터(클라이언트): 유형 3종 · 상태 5종(`new/assigned/contacted/closed/spam`) · 브랜드. 열: 날짜 · 유형 뱃지 · 이름/회사 · 연락처(이메일·전화) · 제품/브랜드 · 배정 브랜드 · 상태 · [보기].
- **[+ 수동 등록]** 모달(전화·메일로 온 리드): type·name·company·email·phone·industry(`users` 업종 목록과 같은 값 — 실제 목록은 `auth/signup.html`에서 찾아라)·message·productId/productName(선택)·brandId/brandName(선택). `source:'admin-manual'`, `status:'new'`, `createdAt: serverTimestamp`(규칙의 `== request.time`과 맞음), `history` 첫 줄, `logAdmin({action:'lead.create'…})`.
- 상세 모달: 연락처·본문·유형·출처 · **배정**(승인 브랜드 select — `brands where status=='approved'`, 배정 시 `brandId·brandName·assignedAt·status:'assigned'` + history + `logAdmin('lead.assign')` + **`mail` 알림 1통**(브랜드 이메일로, `list-your-brand.html`의 `mail.add` 본문 패턴 그대로 — 제목 "New lead assigned — ARCHINODE", 본문에 리드 유형·이름·회사·메시지 요약, 포털 링크)) · 상태 변경 select + 메모 + [저장](history·logAdmin) · `adminNote` · 이력 타임라인.
- 확인창 없음. escapeHtml 전수(연락처·본문은 외부 입력).

### 3. `brand-portal/dashboard.html` (**큰 파일 1035줄 — Node 앵커 삽입, +120줄**) — 탭 「Inbox」
- 기존 탭 구조(`data-tab="brand|products|magazine|settings"`, `#tab-*`)에 `inbox` 추가. 배지: `status=='assigned'` 건수.
- 목록: `db.collection('leads').where('brandId','==',uid).get()` **orderBy 없이** 클라이언트 정렬(복합 색인 회피). 열: 날짜·유형·이름/회사·연락처·메시지(말줄임)·상태.
- 상세(기존 모달 패턴 재사용): 전체 본문 + 상태 select(`assigned→contacted→closed`만) + `brandNote` 한 줄 + [저장] → `update({status, brandNote, updatedAt, history: arrayUnion({...byRole:'brand'})})` — 규칙의 `hasOnly` 4개 키와 정확히 일치해야 한다(다른 키를 같이 보내면 거부됨 — 보고에 키 목록 명시).
- 기존 코드의 `alert()`는 손대지 말고, 새 탭은 인페이지 안내로.
