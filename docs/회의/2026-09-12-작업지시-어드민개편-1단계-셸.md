# 작업지시서 — 어드민 개편 1단계: 사이드바 셸 + 공통 부품 + 대시보드 화면

- **낸 사람**: 지휘 창 (26.09.12 아키노드 #1)
- **하는 사람**: node-white (지휘 창이 Agent 도구로 직접 호출 — 한울님 부재, "알아서 다 해놔" 지시)
- **이 작업은 push·배포를 하지 않는다. 커밋(경로 지정)까지만 하고 「배포 준비됨」이라고 보고한다.**
- **규칙 변경 없음 · 공개 페이지 변경 없음** (어드민 6개 페이지만).
- 정본: `docs/회의/2026-09-12-구현계약서-어드민개편.md` **3장 「1단계」 + 2장 선택지 「나」 + 6장 리스크 1·3·4·5·6·7**. 이 지시서는 그 절을 실행 단위로 옮긴 것이다. 어긋나면 계약서가 이긴다.

## 배경 (처음 보는 사람용)

어드민이 탭 4개짜리 대시보드 + 흩어진 별도 페이지 5개다. 한울님이 "단번 수준의 운영 콘솔"을 지시했고, 노드-골드가 7단계 계약서를 썼다. 1단계는 **그릇**을 만드는 단계 — 왼쪽 사이드바 하나로 어드민 6개 페이지를 묶고, 공통 부품(이스케이프·모달·토스트·다국어)을 한 파일로 올리고, 대시보드 첫 화면(대기 건수 카드 + 최근 활동 자리)을 만든다. **기존 탭 코드(브랜드·제품·아티클·검수관리)는 옮기지 않는다** — 옮기는 건 빼기 작업이라 위험하다.

## 고칠 것

### 1. 새 파일 4개 (`admin/js/`, `admin/admin.css`)

- `admin/js/admin-core.js` (~150줄): `escapeHtml`(기존 615줄과 동작 동일 + **속성용 `escapeAttr`** — `"`→`&quot;` `'`→`&#39;` 추가. 검수대장 A-011 원인) · `t(en, ko)`(현재 언어 텍스트, `document.documentElement.lang` 기준) · `tAttr(en, ko)`(`data-en="…" data-ko="…"` 문자열, escapeAttr 적용) · `tSpan(en, ko)` · `openModal(html)`/`closeModal()`(기존 `#modal`/`#modalContent` 재사용, 없으면 만든다) · `showToast(msg, kind)`(별도 페이지 5개에 있는 것과 같은 모양 — 그 코드를 읽고 복제) · `fmtDate(ts)`(로컬 기준, `toISOString` 금지) · `safeUrl(u)`(`^https?://`만 통과) · `logAdmin(entry)`(**지금은 빈 함수** — 2단계에서 채운다. 주석으로 명시) · `matchText(hay, q)`(여러 단어 AND 부분일치, 6단계용).
  - **선언 방식**: 전역 `function` 선언만. `const`·`let` 전역 금지(별도 페이지 5개가 같은 이름을 각자 갖고 있어 재선언 시 페이지가 죽는다 — 리스크 5). 같은 이름 `function`은 뒤에 오는 것이 이겨 무해.
- `admin/js/admin-nav.js` (~120줄): `ADMIN_MENUS` 배열 하나(묶음: 대시보드 / 고객(리드 인박스·1:1 문의·전문가 회원) / 브랜드(브랜드·제품·아티클·브랜드 후보) / 접수(자문 요청·트렌드 투고·뉴스레터·디지털 알림·아티클 카드형) / 운영(공지사항·활동 로그·검수관리·규정집·설정)). 항목 필드: `{id, en, ko, icon(Font Awesome 클래스 — 페이지가 이미 FA를 쓴다), kind:'tab'|'page'|'view', target, ready:true|false}`. `ready:false`는 **숨김**(아직 없는 화면: 리드·문의·회원·후보·공지·로그·규정집·설정). 사이드바 렌더 + `location.hash` 라우팅(`dashboard.html#review` → 해당 탭 활성) + 별도 페이지에서는 현재 페이지 하이라이트 + 모바일(≤768px) 접기 버튼(햄버거).
- `admin/js/view-dashboard.js` (~120줄): `dash_render(el)` — 대기 건수 카드 6개(브랜드 pending · 제품 pending · 아티클 pending · 자문 pending · 투고 pending · 검수 검토대기) + "최근 활동" 영역(2단계 전까지 `t('Activity log coming in step 2','활동 로그는 2단계에서')` 안내). 카운트는 각 컬렉션 `where('status','==','pending').get()` 단일 필드(복합 색인 회피). 검수관리는 `status=='검토대기'`.
- `admin/admin.css` (~120줄): 사이드바(폭 220px, 흑백 + 골드 `#C8A96E` 활성), 본문 여백, 모바일 접힘, 카드. 기존 인라인 `<style>`과 충돌하지 않게 `.adm-` 접두어.

### 2. `admin/dashboard.html` (**큰 파일 1121줄 — Edit 통째 치환 금지, Node 앵커 삽입. 끝나면 `</html>`·줄 수 확인. ±150줄**)

- `<head>`에 `<link rel="stylesheet" href="admin.css?v=20260912">`.
- 상단바의 별도 페이지 링크 5개(107~111줄 `trend-submissions`·`consultations`·`notify-subscribers`·`newsletter-subscribers`·`articles`)는 **제거하지 말고 `display:none`으로만** 숨긴다(롤백 용이). 사이드바가 그 자리를 대신한다.
- `<div class="admin" id="adminContent">`를 사이드바 + 본문 2단 레이아웃으로 감싼다: `<div class="adm-layout"><aside id="adminSidebar"></aside><div class="adm-main">…기존 내용…</div></div>`. 기존 `.stats-row`·`.tabs`·`.tab-content`는 그대로 `.adm-main` 안에.
- 기존 탭 4개(브랜드·제품·아티클·검수관리)는 사이드바 항목 `kind:'tab'`으로 매핑 — 사이드바 클릭 시 **기존 `.tab` 요소를 프로그램으로 `click()`** 한다(옛 핸들러 무변). `.tabs` 바는 그대로 둔다(사이드바와 이중이지만 1단계에서는 안 뺀다).
- 대시보드 항목(`kind:'view'`)은 새 `<div class="tab-content" id="tab-dashboard">` 하나를 `.tabs` 바 **앞**에 추가하고, 사이드바가 그것을 활성화하면 `dash_render()` 호출. 초기 진입(`#` 없음)은 **대시보드**가 기본이 되게(기존 `brands` 탭 `active` 클래스는 유지하되 페이지 로드 후 라우터가 dashboard로 전환).
- `<script src="js/admin-core.js?v=20260912">`·`admin-nav.js`·`view-dashboard.js`를 `firebase-config.js` **뒤, 기존 인라인 스크립트 앞**에. 기존 인라인의 `escapeHtml`·`closeModal`은 그대로 둔다(뒤 선언이 이긴다 — 동작 동일).
- `loadAll()` 끝에 `dash_render(document.getElementById('tab-dashboard'))` 한 줄(카운트 갱신).

### 3. 별도 페이지 5개 (`admin/consultations.html`·`trend-submissions.html`·`newsletter-subscribers.html`·`notify-subscribers.html`·`articles.html`)

각 파일에 3줄: `<link rel="stylesheet" href="admin.css?v=20260912">` + 본문 최상단 `<aside id="adminSidebar"></aside>`(기존 컨테이너를 `.adm-layout`/`.adm-main`으로 감싸기 — 파일마다 구조가 다르니 **각 파일을 먼저 읽고** 최소 변경) + `<script src="js/admin-core.js?v=20260912"></script><script src="js/admin-nav.js?v=20260912"></script>`(firebase-config 뒤). 각 페이지의 기존 `escapeHtml`·`showToast`가 `const`/`let`이면 **그 페이지는 core를 싣지 말고 nav만** 싣는다(리스크 5) — 어느 쪽인지 보고에 페이지별로 적어라.
