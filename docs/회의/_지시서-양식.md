- **낸 사람**: 지휘 창 (YY.MM.DD 아키노드 #N)
- **하는 사람**: 실행창 (YY.MM.DD 아키노드 #N 실행#1)
- **이 창은 사이트에 올리지도(push) 않고 GitHub 백업도 하지 않는다. 저장(커밋)까지만 하고 「배포 준비됨」이라고 보고한다.**
- 파일 이름 규칙: `docs/회의/YYYY-MM-DD-작업지시-<주제>.md`

## 배경

왜 이 일을 하는지 세 줄 안쪽. 처음 보는 사람이 읽어도 상황이 잡히게.

## 고칠 것

파일·위치·무엇을 어떻게. 완료 조건을 문장으로("모든 카테고리 페이지에서 언어 토글이 동작한다").

## 하지 말 것

- `git add -A` 금지 — 경로를 직접 지정. `git checkout`·`git stash`·`git reset` 금지(다른 창의 작업이 날아간다).
- **200줄 이상 바뀌는 큰 파일(`magazine.html`, `lang.js`, `admin/dashboard.html`, `brand-portal/dashboard.html`)은 Edit 도구로 통째 치환 금지** — 줄 단위 Node 스크립트로. 실제로 두 번 사이트가 죽었다.
- `firestore.rules`를 고쳤으면 "콘솔 재게시 필요"를 보고 맨 위에 적는다(push로는 반영 안 된다).
- 테스트 데이터는 지우지 않는다. `[테스트-○○]` 표시만 달고 무엇을 만들었는지 목록으로 남긴다.
- 보류 영역(작업일지 C절, 다음 단계 B절)은 결함을 발견해도 건드리지 않는다 — 검수 대장에 `보류`로 올리기만.

## 검증

- 코드가 바뀌면 **node-black 필수. CRITICAL이 있으면 저장하지 말고 보고.**
- 로그인이 필요한 확인(어드민·포털)은 **node-bronze**에 넘긴다. 어드민 비밀번호가 없으면 "확인 못 함"으로.
- 다국어(`data-en`/`data-ko`) 짝, 헤더·푸터 표준 구조, 스크립트 로드 경로 깊이 — 블랙 체크리스트 그대로.
