# 작업지시서 — BUG-1: firebase-config.js 무가드 auth() 오류 (검수대장 A-001)

- **낸 사람**: 지휘 창 (26.09.14 아키 #1)
- **하는 사람**: node-white (Agent 도구 직접 호출 — 한울님 부재, 실행창 없음)
- **push·배포하지 않는다. 커밋(경로 지정)까지, 「배포 준비됨」.**
- 규칙 변경 없음.

## 배경

`firebase-config.js`는 홈·카테고리(약 80개)·trend-report·brand-guide 등 auth-compat SDK를 안 싣는 페이지에서도 로드된다. 28줄 `firebase.auth()`가 무가드라 그 페이지들에서 매번 throw → 뒤이은 `db`·`storage`·`isAdmin`이 미정의가 되고, 로그인 상태 표시·트렌드 리포트 목록 등이 조용히 깨진다(5/8부터 잠복, 2026-08-14 브론즈 등록, 한울님 2026-09-14 승인).

## 고칠 것

`firebase-config.js` — 이미 `storage`가 쓰고 있는 것과 같은 패턴으로 `auth`도 조건부 초기화한다.

```js
// 현재 (25~30줄 부근)
firebase.initializeApp(firebaseConfig);
const auth = firebase.auth();
const db = firebase.firestore();
const storage = (typeof firebase.storage === 'function') ? firebase.storage() : null;
```

`const auth = firebase.auth();` 를 `const storage` 줄과 같은 방식으로 바꾼다:

```js
const auth = (typeof firebase.auth === 'function') ? firebase.auth() : null;
```

이 파일 안에서 `auth`를 바로 쓰는 다른 곳(예: `isAdmin()` 함수, `onAuthStateChanged` 등록부)이 있으면 `auth &&` 가드를 추가하거나 null 체크 후 조기 반환하도록 한다 — **파일 전체를 훑어서 `auth.` 호출부를 전부 확인할 것** (단순 초기화 줄 하나만 고치면 그 아래에서 다시 throw할 수 있다).

완료 조건: auth-compat SDK가 안 실린 페이지(예: `index.html`, `categories/furniture.html`)를 열었을 때 콘솔에 `firebase.auth is not a function` 류 오류가 없고, `db`·`storage`가 정상 정의된다. auth-compat이 실린 페이지(로그인·어드민 등)는 기존처럼 정상 동작한다.

## 하지 말 것

- `git add -A` 금지 — `git add firebase-config.js`처럼 경로 지정.
- `auth`가 실제로 필요한 페이지(로그인·프로필·어드민 등)의 기존 동작을 깨지 않는다 — 그 페이지들은 auth-compat을 이미 로드하므로 `typeof firebase.auth === 'function'`이 true가 되어 그대로 동작해야 한다.
- 이 김에 다른 리팩토링 금지(예: storage·db도 재구성 등) — 이 버그 하나만.

## 검증

- node-black 필수, CRITICAL 0.
- 로그인 없이 되는 확인(콘솔 오류 유무)은 화이트가 직접 브라우저로 열어 확인 가능하면 하고, 못 하면 "확인 못 함"으로 남겨 브론즈에 넘긴다.
- auth-compat 로드 여부가 페이지마다 다르므로, 최소 3종(auth-compat 없는 페이지 1개, 있는 페이지 1개 — 예: 어드민이나 로그인, 로그인 상태가 화면에 반영되는 페이지 1개 — 예: index.html 헤더)을 확인.
