# 작업지시서 — 어드민 개편 5단계: 공지사항 + 1:1 문의 (어드민 + 브랜드 포털)

- **낸 사람**: 지휘 창 (26.09.12 아키노드 #1)
- **하는 사람**: node-white (Agent 직접 호출, 한울님 부재)
- **push·배포·규칙 게시를 하지 않는다. 커밋(경로 지정)까지, 「배포 준비됨」.**
- **규칙 변경 있음(`notices`·`inquiries` 신설 — 로그인 사용자 읽기·생성 = 넓히기) · 공개 페이지 변경 없음**(사이트 공지 노출·전문가 문의 폼은 한울님 복귀 후). 게시는 지휘 창.
- 정본: `docs/회의/2026-09-12-구현계약서-어드민개편.md` **3장 「5단계」 + 4-4·4-5절 + 5장 + 6장 리스크 1·4·11**. 4a 커밋 위에 쌓는다(포털 파일을 같이 만지므로 4a 뒤).

## 배경 (처음 보는 사람용)

브랜드에게 알릴 일(검수 기준 변경·전시회 안내·요금 시작)이 생겨도 보낼 창구가 없고, 브랜드가 물어볼 창구도 이메일뿐이다. 엑사·단번 둘 다 공지와 1:1 문의를 관리자 화면 안에 갖고 있다. 5단계는 어드민에서 공지를 쓰고 브랜드 포털 배너에 띄우며, 브랜드가 포털에서 문의를 보내면 어드민 「1:1 문의」에서 답하고 그 답이 포털에 보이게 한다. 메일은 `mail` 콜렉션에만 쌓인다(Extension 설치 미확인 — 발송은 보장 못 함).

## 고칠 것

### 1. `firestore.rules` — 두 블록 (settings 뒤, 기본 차단 앞)
```
    match /notices/{noticeId} {
      allow read: if isAdmin() || (isSignedIn() && resource.data.visible == true);
      allow create, update, delete: if isAdmin();
    }
    match /inquiries/{inquiryId} {
      allow create: if isSignedIn()
                    && request.resource.data.fromUid == request.auth.uid
                    && request.resource.data.status == 'open'
                    && request.resource.data.subject is string && request.resource.data.subject.size() > 0 && request.resource.data.subject.size() < 200
                    && request.resource.data.body is string && request.resource.data.body.size() > 0 && request.resource.data.body.size() < 5000
                    && request.resource.data.createdAt == request.time;
      allow read: if isAdmin() || (isSignedIn() && resource.data.fromUid == request.auth.uid);
      allow update, delete: if isAdmin();
    }
```
`resource.data.get(` 사용 금지. 포털 목록 조회는 `where('fromUid','==',uid)`·`where('visible','==',true)`로만(규칙 문서별 판정).

### 2. `admin/js/view-notices.js` (신규, ~250줄) — 운영 > 「공지사항」
- 필드(계약서 4-4): `title_en/ko`·`body_en/ko`(줄바꿈만, HTML 아님 — 표시 시 escapeHtml + `<br>`)·`audience('brand'|'site'|'all')`·`visible`·`pinned`·`order`·`createdAt/By`·`updatedAt/By`. 목록(고정→order→최신), 등록/수정 모달, 노출 on/off 토글, `logAdmin('notice.save')`. 확인창 없음. 이미지 첨부 없음.

### 3. `admin/js/view-inquiries.js` (신규, ~220줄) — 고객 > 「1:1 문의」
- 상태 `open`/`answered`. 목록(open 먼저·최신), 상세: 보낸 사람(브랜드명/이메일)·제목·본문·답변 textarea·[답변 저장] → `update({status:'answered', answer, answeredAt, answeredBy, history: arrayUnion})` + `mail` 1통(보낸 사람 이메일로, 제목 "Re: <subject> — ARCHINODE", 본문 답변 + 포털 링크) + `logAdmin('inquiry.answer')`. 배지: open 건수(사이드바 + 대시보드 카드).

### 4. `brand-portal/dashboard.html` (**큰 파일, +100줄, Node 앵커 삽입**)
- **상단 공지 배너**: `notices where visible==true` → 클라이언트에서 `audience in ['brand','all']` 필터 → pinned 우선 1건 표시 + 「전체 보기」 모달 목록(제목·본문, 현재 언어).
- **탭 「Support」**: 문의 폼(subject·body) → `add({fromUid:uid, fromRole:'brand', fromEmail, fromName: 브랜드명, subject, body, status:'open', createdAt: serverTimestamp, history:[{status:'open', by:uid, at, note:'등록'}]})` → 규칙의 필드 검사와 정확히 일치. 내 문의 목록(`where('fromUid','==',uid)`, 클라이언트 정렬) + 답변 표시. 인페이지 안내(기존 `alert()`는 손대지 않는다).

### 5. 셸 연결 + 문서
- `admin-nav.js` 공지사항·1:1 문의 `ready:true`, `tab-notices`·`tab-inquiries` div + script(큰 파일). 대시보드 카드 「열린 문의」.
- 루트 `CLAUDE.md` 5절 `notices`·`inquiries`, 3절 포털 설명에 Support 탭·공지 배너. `docs/firestore-schema.md` 두 절(계약서 4-4·4-5).
