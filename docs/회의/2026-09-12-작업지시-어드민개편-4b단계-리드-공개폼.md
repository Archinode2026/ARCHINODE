## 배경 (처음 보는 사람용)

4a로 어드민·브랜드 포털에 리드 인박스가 생겼지만 리드가 들어오는 입구는 어드민 수동 등록뿐이다. 4b는 브랜드 상세(`brands/view.html`)의 「Contact」와 제품 상세(`products/view.html`)의 「Request Info」를 **리드 폼 모달**로 바꿔 방문자가 직접 견적요청·브랜드 문의·딜러 연결을 보내게 한다. 규정집 1-3(가격 비노출 → 문의가 진짜 리드)의 실제 구현이다. **개인정보 제3자 제공 동의 체크 필수**(방문자 연락처가 브랜드에게 간다 — 노드-네이비 문안).

## 고칠 것

1. **동의 문안 먼저** — `node-navy`에게 "리드 폼 동의 체크 문구(KR/EN): 수집 항목·브랜드에 제공·보관 기간·수신 거부" 초안을 받아 폼에 넣는다(리포 `docs/법무/`에 없으면 화이트가 부른다). 문안이 없으면 이 단계를 시작하지 않는다.
2. **공용 리드 폼** `lead-form.js`(신규, 루트, ~200줄): 모달(이름·회사·이메일·전화·업종 select·메시지·유형 hidden·동의 체크) → 검증 → `leads` add(계약서 4-3 필드, `status:'new'`, `source:'brand-page'|'product-page'`, `brandId/brandName`·`productId/productName` 자동, `userId` 로그인 시, `createdAt: serverTimestamp`) → `mail` 어드민 알림 1통(기존 폼 패턴) → 성공 안내(인페이지). `form-throttle.js` 5초 차단 그대로. 로그인한 전문가면 `users` 프로필로 자동 채움. 실패 시 안내(오프라인 대기 안내 포함 — 검수대장 A-010 계열). `data-en/ko` 짝.
3. `brands/view.html`·`products/view.html`: 기존 Contact/Request Info 버튼을 폼 모달 열기로. `firebase-auth-compat.js`가 실려 있는지 확인(없으면 추가 — A-001 계열). 기존 `contact.html`(Formspree) 링크는 푸터 등에 그대로 둔다.
4. 문서: `CLAUDE.md` 5절 leads "4b 공개 폼", 규정집 1-1에 "브랜드·제품 페이지에서 문의가 리드로 들어간다(4b, 날짜)" 한 줄은 **한울님 확정 후 지휘 창이**.
