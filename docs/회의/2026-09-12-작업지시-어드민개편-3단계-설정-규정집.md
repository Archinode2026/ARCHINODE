# 작업지시서 — 어드민 개편 3단계: 설정(settings/config) + 규정집 뷰어

- **낸 사람**: 지휘 창 (26.09.12 아키노드 #1)
- **하는 사람**: node-white (Agent 직접 호출, 한울님 부재)
- **push·배포·규칙 게시를 하지 않는다. 커밋(경로 지정)까지, 「배포 준비됨」.**
- **규칙 변경 있음(`settings` 신설: 읽기 공개·쓰기 어드민 = 넓히기, 개인정보 없음) · 공개 페이지 변경 없음.** 게시는 지휘 창이 화면 push **전에**.
- 정본: `docs/회의/2026-09-12-구현계약서-어드민개편.md` **3장 「3단계」 + 4-2절 + 2-3절 + 5장 + 6장 리스크 4(DOMPurify)·9**. 2단계 커밋 위에 쌓는다.

## 배경 (처음 보는 사람용)

입점 요금 문구("2026년 12월까지 무료, 이후 월 EUR 10")·창립 요금·운영 주체·연락 메일이 공개 페이지 코드에 박혀 있다. 규정집 1-12는 "정책 숫자를 코드에 새로 박지 않는다"인데 고칠 곳이 없다. 3단계는 어드민 「설정」에 그 값을 담는 문서(`settings/config`)를 만들고, 「규정집」 화면에서 결정 정본·작업일지·검수대장을 읽게 한다. **요금 통화는 규정집 안건 1로 미결이라 값은 지금 문구 그대로 옮기고 「안건 1 결정 대기」 빨간 표시.** 공개 페이지가 이 값을 읽게 하는 것은 한울님 복귀 후 별도 단계.

## 고칠 것

### 1. `firestore.rules` — `settings` 블록 (adminLogs 뒤, 기본 차단 앞)
```
    // settings — 정책 값·사이트 정보 (2026-09-12, 개편 3단계). 개인정보 없음. 공개 페이지가 읽을 수 있게 read 공개.
    match /settings/{docId} {
      allow read: if true;
      allow write: if isAdmin();
    }
```

### 2. `admin/js/view-settings.js` (신규, ~250줄) — 운영 > 「설정」
탭 3개(페이지 안 탭, 기존 `.tabs` 패턴 재사용):
- **① 정책 값** — `listing.freeUntilText_en/ko`·`founderText_en/ko`·`freeUntil`(날짜)·`pendingIssue`. **`pendingIssue`가 비어 있지 않으면 각 칸 옆에 빨간 표시 `t('Pending decision — Rulebook issue 1','안건 1 결정 대기 — 규정집 2부')`와 "공개 페이지 연동 전" 안내.** 저장은 된다(막지 않는다 — 계약서 2-3 "칸 옆에 빨간 표시로 막는다"는 시각적 표시를 뜻함).
- **② 사이트 정보** — `site.operator·ceo·bizNo·email·euDirector·euEmail·domain`, `adminNotice`(어드민끼리 메모, 대시보드 상단에 표시).
- **③ 카테고리·어드민** — 읽기 전용: 브랜드 포털 `SUBCATEGORIES`(또는 카테고리 목록이 정의된 실제 파일 — `brand-portal/dashboard.html`에서 찾아라. 없으면 `categories/` 폴더 파일명으로) 10+69 표 + "코드 고정 — 정적 페이지와 1:1" 안내, 어드민 이메일 2개 + "규칙 파일 고정".
- **「기본값 채우기」** 버튼: 문서가 없을 때만 표시. 계약서 4-2의 초기값을 **`for-brands.html`의 실제 문구에서 읽어(파일에서 정확히 옮겨라, 줄 번호를 보고에)** JS 상수로 내장 → `set()`.
- 저장 → `updatedAt`·`updatedBy` + `logAdmin({action:'settings.save', target:{col:'settings',id:'config',label:'config'}, from:'', to:'', note: 바뀐 키 목록})`. 저장 실패 시 토스트로 알린다.
- 대시보드(`view-dashboard.js`)에 `adminNotice`가 있으면 상단 회색 박스로 표시(escapeHtml).

### 3. `admin/js/view-regulations.js` (신규, ~120줄) — 운영 > 「규정집」
- 파일 3개 고정 탭: `../docs/ARCHINODE 규정집.md` · `../docs/작업일지.md` · `../docs/검수대장.md`. `fetch(encodeURI(path))` → 마크다운 렌더.
- 렌더: cdnjs **`marked`**(정확한 버전 고정, UMD) + **`DOMPurify`**(정확한 버전 고정) — `dashboard.html` `<head>`에 `<script src="https://cdnjs.cloudflare.com/ajax/libs/marked/<버전>/marked.min.js">`·`dompurify/<버전>/purify.min.js`. **`DOMPurify.sanitize(marked.parse(md))`** 필수. 표(`table`)가 렌더되게 `marked` GFM 옵션.
- fetch 실패(404·CORS)면 `t('Could not load file','파일을 불러오지 못했습니다')` + 경로 표시. **`docs/`가 GitHub Pages에 공개 서빙되는 것은 검수대장 A-012로 한울님 결정 대기 — 이 화면은 그 사실을 이용할 뿐 새로 여는 게 아니다**(계약서 3단계 주의). 만약 한울님이 `docs/`를 비공개로 결정하면 이 화면은 `settings/regulations`(어드민이 md 본문 붙여넣기)로 바꾼다 — 이번엔 안 한다.
- 목차: h2/h3를 뽑아 왼쪽에 링크(앵커 규칙: 소문자·마침표 제거·공백→하이픈, 엑사 guide.html 방식).

### 4. 셸 연결
- `admin-nav.js` `ADMIN_MENUS`: 설정·규정집 `ready:true`, `kind:'view'`, target `tab-settings`·`tab-regulations`. `dashboard.html`에 두 `tab-content` div + script 2줄(`?v=20260912`). 큰 파일 — Node 앵커 삽입.

### 5. 문서
- 루트 `CLAUDE.md` 5절 `settings/config` 한 줄, 3절 admin 설명에 "설정·규정집(3단계)". `docs/firestore-schema.md`에 `settings/config` 절(계약서 4-2 그대로).
- `docs/ARCHINODE 규정집.md` **2부 안건 1**에 한 줄 추가: "어드민 「설정」 화면에 요금 문구 칸이 생겼다(3단계) — 결정되면 거기서 고치고 공개 페이지 연동 단계(복귀 후)를 연다."

## 하지 말 것
- 공개 페이지(`for-brands.html` 등)가 `settings/config`를 읽게 바꾸지 마라 — 복귀 후 단계.
- 카테고리·어드민 이메일을 설정 문서에 넣지 마라(읽기 전용 표시만).
- `git add -A`·push·규칙 게시 금지. 큰 파일 Edit 통째 치환 금지. `confirm/prompt/alert` 신규 금지. 전역 `const/let` 금지. Browser pane 금지(브론즈 사용 중). Firestore 쓰기 없음.
- DOMPurify 없이 `innerHTML`에 마크다운 결과를 넣지 마라.

## 검증
- `node --check`(새 js 2 + 인라인), `</html>`·줄 수, const/let 표, escapeHtml 전수(설정 값·adminNotice 전부 사용자 값), `data-en/ko` 짝.
- 규정집 렌더는 **로컬에서 실험**: `<script>alert(1)</script>`·`<img onerror>`가 든 md 문자열을 `marked`+`DOMPurify`에 통과시켜 요소가 안 생기는 것을 `new Function`/node로 확인(브라우저 없이 되면 코드검토로 표시).
- 로그인 뒤 저장·읽기·규정집 fetch 실동작은 **못 한다** → 「못 본 것」.
- node-black은 지휘 창이 호출.
