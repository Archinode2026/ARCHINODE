## 배경 (처음 보는 사람용)

가입한 한국 전문가(설계사·디자이너·딜러)가 몇 명이고 무엇에 좋아요를 눌렀는지 어드민이 볼 곳이 없다. 그리고 어드민 화면이 8개 메뉴로 늘어나면서 "그 브랜드 관련된 것 전부"를 한 번에 찾을 길이 없다. 6단계는 **읽기 전용 회원 화면**과 **메모리 캐시만 뒤지는 통합 검색**(엑사 방식 축약)을 붙인다. 회원 삭제는 만들지 않는다(Auth 계정까지 지워야 하는데 서버 코드가 없다).

## 고칠 것

### 1. `admin/js/view-users.js` (신규, ~180줄) — 고객 > 「전문가 회원」
- `db.collection('users').orderBy('createdAt','desc').limit(200).get()` + 「더 보기」. **필드 이름은 `auth/signup.html`·`auth/profile.html`이 실제로 쓰는 것을 읽고 맞춰라**(스키마 문서 `users` 절과 대조, 다르면 보고).
- 목록: 이름 · 회사 · 업종 · 가입일 · 좋아요 수(제품/브랜드). 필터(클라이언트): 업종. 상세 모달: 프로필 + 좋아요한 브랜드/제품 **이름 풀기**(brands·products 캐시에서 id→이름, 캐시에 없으면 id 그대로 + "(삭제됨/비공개)").
- **삭제·정지 버튼 없음.** CSV 내보내기는 `admin/newsletter-subscribers.html`의 `downloadCSV`(실제 함수명 확인)를 `admin-core.js`로 올려 재사용(그 페이지는 자기 것을 계속 쓴다 — 뒤 선언이 이김).
- 개인정보: 이메일·전화는 상세에서만, 목록엔 이름·회사만. escapeHtml 전수.

### 2. 통합 검색 — `admin-core.js` `searchAll(q)` + `admin-nav.js` 검색창 (~120줄)
- 사이드바 상단 검색창(돋보기). 입력 300ms 디바운스. **추가 읽기 없음** — 각 화면이 이미 불러온 캐시(`reviewCache`·리드·회원·brands·products·articles 목록 변수 — 실제 변수명은 각 view/인라인에서 찾아 `admRegisterCache('brands', arr)` 식으로 등록하게 한다)만 뒤진다. 여러 단어 AND, 부분일치(대소문자 무시), `matchText()` 재사용.
- 결과 드롭다운: 종류 뱃지 + 이름 + 부제(브랜드는 국가/카테고리, 리드는 유형/상태, 회원은 회사). 클릭 → 해당 화면(사이드바 항목 활성) + 상세 모달(각 화면의 `view○○(id)` 함수 호출 — 없으면 화면만). 별도 페이지 컬렉션(자문·투고·뉴스레터·알림)은 "그 페이지로 이동" 항목 하나만.
- 초성 검색 없음. 결과 최대 30건.

### 3. 셸 연결
- `admin-nav.js` 전문가 회원 `ready:true` target `tab-users`. `dashboard.html`에 `tab-users` div + script(큰 파일 — Node 앵커 삽입). 대시보드 카드에 「회원 수」 1장(총원, `users` 캐시 길이 — 200 초과면 "200+").

### 4. 문서
- 루트 `CLAUDE.md` 3절 admin 설명에 "회원·통합 검색(6단계)". `docs/firestore-schema.md` `users` 절이 실제 필드와 다르면 정정(정정한 내용을 보고에).
