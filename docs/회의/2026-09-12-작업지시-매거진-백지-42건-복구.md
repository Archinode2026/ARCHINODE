# 작업지시서 — 매거진 기사 백지 42건 복구 (검수대장 A-013)

- **낸 사람**: 지휘 창 (26.09.12 아키노드 #1)
- **하는 사람**: node-white (Agent 직접 호출)
- **push·배포하지 않는다. 커밋(경로 지정)까지, 「배포 준비됨」.** ★ **공개 페이지 변경 — push는 한울님 「배포할까요?」 승인 후**(부재 중 공개 페이지 배포 금지 기본값).
- 규칙 변경 없음.

## 배경 (처음 보는 사람용)

매거진 목록에서 기사를 누르면 116편 중 42편이 **흰 화면**만 뜬다(브론즈 2026-09-12 R5 실측, 라이브=로컬). 원인: 기사 파일 34행 `<style>` 블록이 `.article-hero{…url('../assets/magazine/placeholders/inte` 에서 **잘린 채** 곧바로 공지 바 마크업이 이어져 `</style>`·`</head>`·`<body>`가 없다 → 브라우저가 문서 전체를 CSS로 읽는다. 5월 6일(e985d7c)부터 있었고 오늘 자동 발행 3편(1b4f583)도 같은 모양 → **자동 발행 템플릿이 깨진 원본을 복제 중**. 파이프라인 자체(Cowork 계정 스킬 `mag-*`)는 리포 밖이라 한울님 몫이고, 이 지시서는 **리포 안 42개 파일만** 고친다.

## 고칠 것

1. **목록 확정**: `archi-diary/bronze-2026-09-12.md` 5-2의 42건 목록을 읽되 믿지 말고 **다시 세라**(철칙: 사전 수치 검증) — `magazine/*.html` 전부에서 `</style>` 부재 또는 `<body` 부재 파일을 grep. 개수가 42와 다르면 다르다고 보고.
2. **정상본과 대조**: 정상 기사(브론즈가 지목한 `magazine/agm-thermroof-*.html` 38~40행 등 `</style></head><body>`가 있는 파일)에서 잘린 자리의 **원래 CSS 끝부분**(`.article-hero{…url('../assets/magazine/placeholders/interior.svg')…}` 등)을 확인한다. 잘린 파일들이 같은 지점에서 끊겼는지, 잘린 뒤 이어지는 마크업이 정상본의 `<body>` 첫 부분과 같은지 대조해 **복구 규칙 하나**를 만든다(예: 잘린 `url('…/inte` 뒤에 정상본의 나머지 CSS + `</style></head><body>`를 삽입).
3. **Node 스크립트로 42건 일괄 복구** — 파일마다 (a) 잘린 지점이 규칙과 정확히 일치하는지 검사(불일치면 건너뛰고 목록에), (b) 삽입, (c) 결과에 `<style>`·`</style>`·`</head>`·`<body`·`</body>`·`</html>`이 각 1회 이상 있는지, 줄 수가 줄지 않았는지 확인. 스크립트는 `tools/fix-magazine-blank.js`로 저장(재발 시 재사용).
4. **검증**: 복구된 파일 3건을 정상본과 구조 diff(헤더·공지 바·본문 시작). 특수문자 생존(`${`·백틱 없음이 정상). 한 파일을 임의로 골라 인라인 스크립트 `node --check`.
5. `magazine.html` 카드는 손대지 않는다(링크는 이미 맞다).
6. 문서: `docs/검수대장.md` A-013 상태 `확인대기`, 이력에 "09-12 화이트 복구 커밋 <해시> — 브론즈 라이브 재확인 대기, 파이프라인 템플릿은 한울님". 루트 `CLAUDE.md` 8절 함정에 한 줄: "매거진 자동 발행 템플릿이 `<style>` 잘린 채 복제(A-013) — 새 기사는 `</head><body>` 존재를 블랙이 검사".
