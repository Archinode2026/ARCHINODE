## 배경 (처음 보는 사람용)

어드민에서 브랜드를 정지하거나 글을 거절해도 **누가 언제 왜 했는지** 어디에도 남지 않는다. 사유는 마지막 것 하나만 덮어씌워진다(검수대장 A-009). 2단계는 어드민의 모든 상태 변경을 **덧붙이기만 되는 장부(`adminLogs`)**에 남기고, 브랜드 문서에는 `history[]` 배열로 이력을 쌓는다. 대시보드 "최근 활동"이 이 장부를 읽는다.

## 고칠 것

### 1. `firestore.rules` — `adminLogs` 블록 (reviewIssues 뒤, 기본 차단 앞)
```
    // adminLogs — 어드민 활동 장부 (2026-09-12, 개편 2단계). 덧붙이기만 된다: 어드민이라도 수정·삭제 불가.
    match /adminLogs/{logId} {
      allow create, read: if isAdmin();
      allow update, delete: if false;
    }
```
`brands` 규칙은 손대지 않는다(어드민 update 조건이 status 4값만 검사하므로 `history` 필드 추가에 변경 불필요 — **실제 규칙 파일에서 그 사실을 확인하고 보고에 적어라**. 만약 `hasOnly`류로 필드를 제한하고 있으면 멈추고 보고).

### 2. `admin/js/admin-core.js` — `logAdmin(entry)` 채우기
계약서 4-1 필드 그대로: `{at: serverTimestamp, by: auth.currentUser.email, action, target:{col,id,label}, from, to, note, page}`. `page`는 파일명(`location.pathname` 마지막 조각). **실패해도 화면 흐름을 막지 않는다** — `try/catch`로 감싸되 콘솔에 `console.warn('[adminLogs] 기록 실패', e)` 남기고 `showToast('활동 기록 실패 — 개발 메모 참조','warn')` 한 줄(조용한 실패 방지 — 사용자는 실패를 안다). `db`가 없으면 아무것도 안 함.

### 3. 기존 코드에 `logAdmin` 한 줄씩 + `brands.history`
- `admin/dashboard.html` (**큰 파일 1136줄 — Node 앵커 삽입, ±25줄**):
  - `updateBrand(docId, newStatus)`: `update()` 성공 직후 `history: firebase.firestore.FieldValue.arrayUnion({status:newStatus, by:email, at:new Date().toISOString(), note: reason||''})`를 **같은 update에 포함**(두 번 쓰지 말 것) + `logAdmin({action:'brand.status', target:{col:'brands',id:docId,label:brandName}, from:이전status, to:newStatus, note:reason})`.
  - `updateDoc(collection, docId, status)`(제품·아티클): `logAdmin({action: collection==='products'?'product.status':'article.status', …})`. 이전 값은 update 전에 읽은 문서에서(이미 `get()`하는 흐름이면 재사용, 아니면 한 번 읽기).
  - 검수관리 `saveReviewStatus`(또는 상태 저장 함수 — 실제 이름은 파일에서 찾아라): `logAdmin({action:'review.status', target:{col:'reviewIssues',id, label: no}, from, to, note})`.
  - `viewBrand` 상세 모달에 **「이력」 절** 추가: `b.history`가 있으면 최신 위로 `status · by · at(fmtDate) · note` 목록, 없으면 `t('No history yet','이력 없음')`. escapeHtml 전수.
- 별도 페이지 5개의 상태 변경 함수(`doAction` 또는 각 파일의 실제 이름 — **파일마다 읽고 찾아라**)에 `logAdmin({action:'consultation.status'|'trend.status'|'newsletter.status'|'notify.status'|'article.status', …})` 한 줄씩. 각 파일 ~5줄.

### 4. `admin/js/view-logs.js` (신규, ~150줄) + 메뉴 켜기
- 운영 > 「활동 로그」: `db.collection('adminLogs').orderBy('at','desc').limit(100).get()` **단일 필드 orderBy**(복합 색인 금지). 표: 시간(fmtDate) · 누가 · 무엇을(action 라벨 `data-en/ko`) · 대상(label + col/id 작게) · 어디서→어디로 · 메모 · 화면. 필터(클라이언트): 기간 오늘/7일/30일 · 종류(action 접두어). 「더 보기」는 `startAfter` 로 100건씩.
- `admin-nav.js`의 `ADMIN_MENUS`에서 활동 로그 항목 `ready:true`, `kind:'view'`, target `tab-logs`. `dashboard.html`에 `<div class="tab-content" id="tab-logs">` 1개 추가(앵커: `tab-dashboard` div 뒤) + `<script src="js/view-logs.js?v=20260912">`.
- `view-dashboard.js` "최근 활동" 자리를 `adminLogs` 최신 20건으로 채운다(같은 렌더 함수 재사용).
