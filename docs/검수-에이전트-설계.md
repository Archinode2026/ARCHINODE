# 검수 항목 처리 에이전트 — 설계안

> 2026-11-05 작성. 이 세션에서 검수관리 24건(HIGH 2 + 검토대기 22)을 처리하며 실제로 쓴
> 기준을 뽑아 정리한 것. 아직 만들어진 에이전트가 아니라 **구상안**이다.

---

## 1. 왜 자리가 비어 있나

지금 에이전트는 네 역할로 나뉘어 있다.

| 에이전트 | 하는 일 | 안 하는 일 |
|---|---|---|
| 브론즈 | 실제 브라우저로 돌아다니며 결함을 **찾아** 보드에 등록 | 고치지 않는다 |
| 골드 | 코드 쓰기 전 **설계** | 코드를 안 쓴다 |
| 화이트 | 지시서를 받아 **구현**·커밋 | 로그인이 필요한 확인을 못 한다 |
| 블랙 | 배포 전 **정적 검사** | 발견만 하고 안 고친다 |

**등록된 R- 항목 하나를 받아 끝까지 닫는 일**에는 주인이 없다. 그 일은 고치는 것(화이트)과
검증하는 것(블랙)에 걸쳐 있는데, 둘 다 갖고 있지 않은 세 가지가 더 필요하다.

1. **고치기 전 상태를 되살려 재현하고 숫자로 재기**
2. **장부(`docs/검수대장.md`)에 A- 번호로 기록**
3. **상태 판단** — 확인완료 / 오탐반려 / 확인대기(사람 판단 필요)

---

## 2. 24건에서 실제로 나온 사실

이 기준이 왜 필요한지는 이번 24건이 그대로 보여 준다.

- **9건은 이미 고쳐져 있었다.** R-018·R-048·R-064·R-002·R-006·R-028·R-037·R-039·R-038.
  신고 시점(9월 중순)과 처리 시점 사이에 다른 작업이 함께 풀었다.
  → **"고쳐졌다" 는 말만으로 닫으면 안 된다.** 어느 커밋이 풀었는지 찾고(`git log -S`, `git log -L`),
  고치기 전 상태로 한 번 재현해 본 뒤에 닫아야 한다. 그러지 않으면 "아마 됐을 것" 을 기록으로 남긴다.

- **3건은 신고보다 범위가 넓었다.** R-065(신고 1곳 → 실제 4곳), R-069(5곳 → 8곳 + 안 붙인 4곳),
  R-007(한 화면 → 공용 CSS 라 전 화면).
  → **신고된 파일만 고치면 절반만 고친다.**

- **1건은 원인이 신고자 추측과 달랐다.** R-027 은 "집계 기준이 다른 것 같다" 였는데, 실제로는
  기준이 처음부터 같았고 **제출 뒤 카드를 다시 읽지 않는 것**이 원인이었다.
  → **추측은 단서로만 쓰고, 원인은 코드에서 다시 찾는다.**

- **2건은 결함이 아니었다.** R-049(등록자 본인이 테스트 데이터라고 적음), R-017(진짜 휠 입력으로
  재 보니 정상 동작).
  → **오탐도 증명해서 닫는다.** R-017 은 신고자가 "자동화 도구라 확신 못 한다" 고 덧붙였고,
  그 걱정을 그대로 짚어 **진짜 입력 장치 이벤트**로 다시 쟀다.

- **내가 만든 회귀를 3번 잡았다.** A-222(안내 문구에 화면 언어가 굳음), A-223(메모 열을 고쳤더니
  희생되는 열이 「대상」 으로 옮겨감 / `min-width` 가 더 또렷한 규칙에 져서 열 폭이 0 이 됨).
  → **고친 뒤 같은 자로 다시 재지 않으면 내가 새 결함을 넣는다.**

## 3. 처리 절차 (7단계)

```
① 신고 읽기      → 보드에서 원문·개발 메모·이력까지 전부
② 범위 다시 재기  → 같은 꼴이 저장소에 몇 군데인지 전수로 센다
③ 재현           → git show HEAD:<파일> 로 고치기 전 사본을 만들고 숫자로 잰다
④ 고치기         → 뿌리를 고친다. 같은 꼴이 여러 곳이면 공용 자리에 한 번
⑤ 다시 재기      → ③과 같은 자로. + 내가 만든 회귀 확인(하네스·검사 스크립트)
⑥ 장부           → A- 번호로 11칸 한 줄. 전/후 숫자와 '안 고친 것과 그 이유' 포함
⑦ 상태 판단      → 확인완료 / 오탐반려 / 확인대기
```

③과 ⑤에서 **같은 자**를 쓰는 것이 핵심이다. 전은 재지 않고 후만 재면 "고쳤다" 가 주장이 된다.

## 4. 상태를 가르는 기준

| 상태 | 언제 | 예 |
|---|---|---|
| **확인완료** | 고쳤고 전/후 숫자로 증명됨. 또는 이미 고쳐져 있었고 그것을 증명함 | A-222 상태 5가지 전수 · A-240 라이브에서 돌아오는 길 확인 |
| **오탐반려** | 결함이 아님을 증명함 | A-224 등록자가 테스트 데이터라 적음 · A-245 진짜 휠로 정상 확인 |
| **확인대기** | **사람이 정해야 할 것이 남음** | 한국어 문구 선택, 제품 결정, 실계정·실데이터가 필요한 확인 |

**확인대기로 미루는 기준은 "내가 못 해서" 가 아니라 "내가 정하면 안 돼서" 다.**
문구·이름·제품 결정은 고쳐 놓더라도 승리에게 한 줄로 물어본다 — A-206 에서 낡은 주석을 믿고
혼자 판단했다가 회귀를 만든 적이 있다.

## 5. 이 저장소에서 반복해 나온 함정

새 에이전트가 가장 먼저 의심해야 할 목록. 전부 이번 세션에서 실제로 터진 것들이다.

1. **화면 언어가 그릴 때 굳는다.** `textContent` 로만 넣으면 `lang.js` 가 다시 칠하지 못한다.
   → `data-en`/`data-ko` + `applyLangAgain()`. `setLang()` 은 사용자 선택을 저장하므로 쓰지 않는다.
   (A-222 · A-226 · A-227 · A-228)
2. **이스케이프가 못 막는 것들.** `javascript:` 스킴에는 이스케이프할 글자가 없다(A-218).
   `escapeAttr` 로 넣은 `&#039;` 는 파서가 풀어서 JS 소스가 된다(A-229).
   `toLocaleString()` 은 인자가 없으면 시스템 언어를 따른다(A-226).
   → **"맞는 함수를 불렀는가" 가 아니라 "실제로 무엇이 일어나는가" 를 본다.**
3. **표에 폭 규칙이 없으면 어느 한 열이 1글자씩 쌓인다.** 한 열만 고치면 희생자가 옮겨 갈 뿐이다.
   → `table-layout: fixed` + 열 폭 + `.adm-table-wrap`. (A-223 · A-225)
4. **숫자가 묵는다.** 목록만 다시 읽고 카드·카운트는 안 읽는 자리가 반복된다. (A-200 · A-238)
5. **공유 CSS 는 명시도 싸움이다.** `.adm-table-wrap > table` 이 `.adm-log-table` 을 이긴다. (A-223)
6. **데이터가 없으면 안 보인다.** Firebase 가 막힌 환경에서는 표가 비어 있어 넘침이 안 생긴다.
   → 가짜 Firestore 에 **실제 분포**를 심는다. 합성 데이터가 느슨하면 재현에 실패한다(A-225).
7. **디자인 변경이 상자를 지운다.** 테두리를 걷으며 `width/height: auto` 로 돌리면 누르는 면적이
   글자 크기로 주저앉는다. (A-237)

## 6. 쓸 수 있는 도구

- **저장소**: `device_bash` — 읽기·수정·`git`. push 는 못 한다(승리가 한다).
- **측정**: 별도 컨테이너의 Playwright + `python3 -m http.server`. 저장소 사본을 올려 재현.
  **반드시 md5 로 저장소와 사본이 같은지 확인한 뒤 잰다**(A-195 에서 낡은 사본을 재고 결과를 낸 적 있음).
- **라이브·실데이터**: Claude in Chrome — 승리가 로그인해 둔 Chrome. 보드 읽기·상태 저장,
  실제 콘솔·실제 데이터 분포 확인. **비밀번호는 입력하지 않는다.**
- **상시 검사**: `scripts/check_escaping.py`(정적) · `check_xss_output.py` · `check_narrow_width.py`,
  전체 사이트 하네스(53행) · 어드민 하네스(14행).
