## 숫자를 다시 센 것 두 가지

브론즈의 지적이 **틀린 것은 아니지만, 그대로 고치면 엉뚱한 데를 고치게 되는**
자리가 둘 있었습니다. 둘 다 다시 재고 갈랐습니다.

### N49-5 — 「44px 미만 27개」 → 진짜로 손봐야 할 것은 **한 곳**

- 보이는 상자로만 세면 24x24(WCAG 2.2 **AA** 2.5.8) 미달이 **48종**입니다.
- 그런데 2.5.8 에는 **간격 예외**가 있습니다 — 24px 원이 서로 안 겹치면 통과.
  꼬리말 링크들은 줄 간격이 충분해 **전부 예외**를 받습니다. → 48종 → **1종**.
- 그 1종(`.hero-dot`)도 보이는 상자는 32x2 지만 `::after` 로 과녁을 넓혀 두었고,
  **elementFromPoint 로 실제 히트 영역**을 재야 참이 보였습니다.
  → 모바일은 이미 44px, **데스크톱만 2px** 였습니다. 그쪽만 24px 로 올렸습니다.
- 44x44 는 **AAA**(2.5.5)이고, A-356 에서 「손가락 기준, 데스크톱엔 적용 안 함」으로
  이미 정하신 건입니다. 그 결정은 건드리지 않았습니다.

### N49-6 — 「백업 쪽」 → 저장소엔 없고, 대신 **더 넓은 것**이 나옴

- 브론즈가 든 `_blyb.html` · `_bmag.html` 은 **저장소에 없습니다.**
  라이브에만 남은 옛 배포물로 보이는데, 확인하지 못했습니다.
- 대신 저장소에서: Netlify 가 `publish = "."` 로 전부 올리는데
  `admin/` 7쪽과 `brand-portal/dashboard.html` 에 **noindex 가 하나도 없었습니다.**
- **먼저 접근 위험인지부터 봤습니다 — 아니었습니다.** firestore.rules 705줄에서
  관리 쓰기 열두 자리가 전부 `isAdmin()`(이메일 허용목록)을 거칩니다.
  막은 것은 **노출**이지 접근이 아닙니다.

## 오늘 세 번 되풀이된 것 — 「있다」와 「듣는다」는 다른 질문

- A-640: 인쇄용 히어로 숨김이 **적혀는 있었는데** 특정도에 져서 몇 달간 안 들었습니다.
  (A-412 · A-630 에 이어 **세 번째**였습니다. 인쇄 규칙은 이제 전부 `html body` + `!important`.)
- A-641: 처방 검사기가 `/* */` **주석 안에 적힌 규칙을 「있다」로 읽고** 있었습니다.
  처방 12종 전부가 같은 구멍이었습니다. (A-619 에 이어 두 번째.)
- A-643: A-237 이 231쪽에 건너뛰기 링크를 넣을 때 **「있는가」만 세고 「첫째인가」는** 안 셌습니다.
