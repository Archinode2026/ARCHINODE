## 4. `mail` 컬렉션 — 자문 요청 알림 메일 존재 여부 (A-064/A-033/A-021 관련)

- **콘솔에서 읽기 전용 조회(`get()`)로 직접 확인**: `db.collection('mail').where('message.subject','>=','[ARCHINODE] 컨설팅').where('message.subject','<','[ARCHINODE] 컨설팅').get()` → **0건**. 자문 요청용 관리자 알림 메일 문서가 단 하나도 생성되지 않음을 재확인(E 라운드의 간접 확인을 직접 쿼리로 재확증).
- 코드 확인(`request-consultation.html:482~506`): `consultations` 저장 성공 후 별도 `try` 블록에서 `dbRef.collection('mail').add({...})`를 호출하는데, 이 객체 리터럴 안에서 `data.companyName` 등 `data.*`를 참조함. 그런데 이 함수 스코프엔 `data`라는 변수가 없음(실제 변수는 `companyName`·`contactName`·`email`·`phone`·`country`·`category`·`timing`·`budget`·`description` 개별 변수) → 객체 리터럴을 평가하는 시점에 `ReferenceError: data is not defined`가 발생하고, 이 전체가 `catch(mailErr){ console.warn(...) }`로 조용히 삼켜짐. 즉 `mail.add()` 호출 자체가 한 번도 실행되지 못하고 매번 실패 — 콘솔 조회 결과(0건)와 정확히 일치.
- **어드민 검수관리 탭에서 A-021·A-033을 확인**: 두 항목 모두 `request-consultation.html`의 이 관리자 알림 메일 실패를 다루고 있고, 이미 A-033에 "A-021과 중복, 판정은 A-021 기준" 메모가 있음. 지시대로 **새 항목 등록은 하지 않고**, A-021(마스터 판정 대상)에 UI로 상태값은 그대로 둔 채(검토대기 → 검토대기) 이력 메모를 추가함: "브론즈-E4 재확인(09-16): mail 컬렉션을 자문 알림 제목 패턴으로 직접 조회 → 0건 확인. 코드(request-consultation.html 483~500줄, data 미정의)도 재확인 — 조용한 실패가 아니라 완전 무발송으로 이어짐." (상태 저장 버튼은 confirm/prompt를 쓰지 않는 일반 폼 제출임을 소스코드로 먼저 확인한 뒤 실제 UI 클릭으로 진행, 클릭 직전 `firebase.auth().currentUser.email`이 `wool21wool@gmail.com`임을 재확인함— 철칙 12·13 준수)
