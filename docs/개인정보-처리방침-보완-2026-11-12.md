## 3. ★ 페이팔 — 먼저 알려 주셔야 하는 것

**지금 코드에는 결제 연동이 없습니다.** `digital-products.html:579` 가
「PayPal 통합은 Step 2-D (페이팔 계정 검증 후) 활성화 예정」이고, 주문은
`mailto:office@archinode.org` 로 **메일을 보내는 것**이 전부입니다.

그래서 처리방침 문장이 두 갈래로 갈립니다. **어느 쪽입니까?**

- **ㄱ. 지금처럼 수동 인보이스** — 손님이 메일로 주문 → 승리님이 PayPal 에서 인보이스 발행.
  이때 PayPal 로 가는 것은 **승리님이 입력하는 손님 이메일·이름**입니다.
  → 「결제 처리를 위해 PayPal 에 이메일·성명을 제공」으로 적습니다. 사이트는 아무것도 안 보냅니다.
- **ㄴ. 사이트에 결제를 붙인다**(Smart Buttons / Payment Link) — 그러면 **손님 브라우저가
  PayPal 과 직접 통신**하고 쿠키도 붙습니다. 처리방침·쿠키 고지 양쪽을 그에 맞게 써야 하고,
  CSP 에 PayPal 도메인도 열어야 합니다(지금은 막혀 있어서 **붙여도 안 돕니다**).

**ㄴ 로 가실 거면 코드 작업이 먼저입니다** — 말씀해 주시면 CSP·버튼·주문 기록까지 한 묶음으로 하겠습니다.

## 5. 승리님이 정하실 것

1. **`country.is` (IP 전송)** — 둘 중 하나입니다.
   - **ㄱ 고지한다** — 위 표에 한 줄 더합니다.
   - **ㄴ 끈다** ← 제 추천. A-359 에서 **브라우저 언어를 1순위 신호로** 바꿔 둬서, IP 조회는
     지금 **보정 역할만** 합니다. 빼도 한국어 브라우저는 그대로 한국어로 열립니다.
     **고지할 것이 하나 줄고, 첫 화면도 빨라집니다.** 30분이면 뺍니다.
2. **페이팔** — 위 3번의 ㄱ/ㄴ.
3. **영문판**(`privacy-en.html`) — 같은 내용으로 맞춰 드릴까요? 지금 한글판과 조문 번호가 같습니다.
4. **보유기간** — 표의 「위탁계약 종료 시까지」는 제가 관례대로 적은 것입니다. 실제 계약과 다르면 알려 주세요.

## 7. 추가 — 「결제 건수를 계속 봐야 하나」 (2026-11-12 질문)

**ㄱ(결제 링크) 그대로면: 네, 수동입니다.** PayPal 이 결제마다 `office@archinode.org` 로
알림 메일을 보내고 대시보드에도 쌓이지만, **우리 사이트는 그 사실을 모릅니다.**
그래서 「메일을 보고 → 파일을 보낸다」가 됩니다.

사이에 중간 길이 하나 있습니다.

| | 작업 | 결과 |
|---|---|---|
| **ㄱ** 결제 링크만 | 반나절 | 결제는 열리지만 **확인·전달 모두 수동** |
| **ㄱ+** 링크 + **웹훅** | **1일** | PayPal 이 결제 즉시 우리 쪽에 알려 줍니다 → 주문이 **어드민 화면에 자동으로 뜹니다**. 전달은 수동이거나, 원하면 메일 자동 발송까지 |
| **ㄴ** Smart Buttons | 2~3일 | 사이트 안에서 결제까지. CSP·서버 검증·주문·파일 전달 전부 |

**ㄱ+ 의 내용**: Netlify Function 하나가 PayPal 웹훅을 받아 서명을 검증하고
`orders` 컬렉션에 한 줄 적습니다. 어드민에 「주문」 화면을 붙입니다.
클라이언트 SDK 가 없으니 **CSP 는 그대로**이고, 결제는 여전히 PayPal 페이지에서 일어납니다.

**지금은 ㄱ 으로 시작하고, 주문이 한 주에 몇 건 넘어가면 ㄱ+ 로 올리는 것**을 권합니다.
상품이 0건인 지금은 ㄱ+ 를 만들어도 들어올 주문이 없습니다.
