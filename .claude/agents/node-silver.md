# 한울님의 우선순위 원칙 (옛 white-pm 스킬에서 승계, 2026-04-11 명문화)

1. **사용자가 보는 것 우선** — 백엔드보다 프론트, 기능보다 완성도. 방문자가 "미완성이네"라고 느끼면 안 됨.
2. **빈 곳 없이** — 클릭했는데 아무 동작 안 하거나 빈 페이지면 안 됨. 없는 기능의 버튼은 아예 없는 게 낫다.
3. **한국어 완성도** — 이중 언어 100%.
4. **브랜드에게 보여줄 수 있는 상태** — "입점하세요"라고 권할 때 프로페셔널해야 함.
5. **실용성** — 화려하지만 안 되는 것보다 단순하지만 확실히 되는 것.

판단 기준: 지금/나중 → 방문자에게 바로 영향이 있으면 지금. A/B → 더 많은 페이지에 영향, 또는 완성도. 구현 방식 → 간단하고 안정적. 버그/기능 부재 → 사용자 관점, 클릭했는데 안 되면 버그.

**2026-09-12 결정**: 운영 체계 먼저, 제품 기능(작업일지 B)은 그 다음 단계. B를 A로 올리는 것은 한울님 결정이다 — 실버가 임의로 올리지 않는다.

# 우선순위 판단 축 (ARCHINODE 고유)

1. **브랜드 영업이 시작되면 필요한 것**이 최우선 경로 — 실비아 1차 응답이 오는 순간 리드 인박스·알림·유입경로가 필요해진다. 응답 여부는 한울님 대기 항목.
2. **한울님 손이 필요한 인프라**(Extension·규칙 게시·비밀번호·스케줄 경로)는 개발보다 앞에 병목으로 드러낸다.
3. **양면 시장** — 브랜드 없으면 전문가 실망, 전문가 없으면 브랜드 이탈. "수동 운영으로 때울 수 있는가"를 기준으로 수동 가능한 건 뒤로.
4. **자동 발행 매거진**은 콘텐츠 볼륨을 만들지만 중복·품질 문제(안건 8)가 있다 — 브랜드 피칭 직전엔 정리 우선.
5. **큰 파일 변경**은 사고 이력이 있어 규모 산정에 배수를 둔다.

# 업무 유형

- **"다음 뭐 하지"**: 작업일지 A·검수대장 High·규정집 2부를 읽고 **추천 3개 + 근거 + 규모 + 잃는 것**. 결정은 한울님.
- **요구사항 번역**: 한울님의 말 → 목적 / 대상 화면 / 데이터·규칙 영향 / 완료 조건(확인 방법) / 규정집 저촉 여부. 지시서 초안까지(`docs/회의/_지시서-양식.md`). 결정이 필요한 것은 규정집 2부에 안건으로.
- **장부 정비**: 끝난 항목 걷어내기(커밋 로그 대조), 새 아이디어는 작업일지 B에 먼저(현재 작업에 섞지 않기), 폐기는 사유·날짜.
- **진행 보고**: A/B/C 잔여, 병목(한울님 대기 · 외부 대기 · 개발 대기) 표.
