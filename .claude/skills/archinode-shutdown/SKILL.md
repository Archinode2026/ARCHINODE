# 아키노드-종료 (하루 마감 절차)

> 짝이 되는 시작 절차는 **`archinode` 스킬**(지휘 창)이다. 엑사의 `exa-shutdown`을 옮겼고 원조는 단번의 `danbunn-shutdown`.
> 목적은 둘 — **오늘 한 일이 하나도 안 새는 것**, **다음 세션이 파악에 시간을 안 쓰는 것**.
> 이 프로젝트에서 실제로 벌어진 일: 7월 16일 이후 **두 달간 push 공백**, 홈 화면 결함이 **한 달간 승인 대기**, "다음 할 일"이 **다섯 문서에 분산**. 이 절차는 그 셋을 막기 위해 있다.

⚠️ 이 절차의 산출물은 "한울님이 읽는 보고" 하나다. 도구를 호출한 것, 커밋한 것은 완료가 아니다 — **push까지, 규칙은 콘솔 게시까지** 끝나야 완료다.

## 0단계 · 돌고 있는 것부터 확인

백그라운드 작업(실행창·에이전트·매거진 자동 발행)이 있으면 먼저 "무엇이 몇 개 돌고 있고, 기다릴지 끊을지" 여쭙는다. 끝났는데 안 읽은 결과가 있으면 읽고 반영한다. **결과를 추측해서 기록하지 않는다.**

## 1단계 · 이 세션부터 저장

리포 루트(`.git`이 있는 최하위 폴더)에서:
```
git status --short                          → 미커밋
git rev-list --left-right --count origin/main...main   → 미푸시 (0 0 이어야 함)
```
- **미푸시 커밋은 종료의 1순위 위험이다.** 이 프로젝트는 GitHub Pages라 push가 곧 배포이므로, "커밋만 하고 push 안 함"은 "고쳤는데 사이트엔 안 나감"이다.
- 변경이 남아 있으면 커밋한다 — 무엇을 왜, 한국어로. **단, 사이트에 나가면 안 되는 미완성 코드가 섞여 있으면 커밋하지 말고 4단계 3항으로 보고한다.** push는 `tools/deploy.ps1`로(라이브 대조까지).
- 50 파일이 넘으면 GitHub Desktop으로 한울님이. 그 경우 "한울님이 해야 할 것"에 올린다.

## 2단계 · 나머지 세션 훑기

한울님은 여러 창을 동시에 띄운다. "종료"라고 말한 세션 하나만 보면 하루의 대부분을 놓친다.
1. `list_sessions`로 **오늘 이 리포 폴더에서 활동한 것**만 추린다(「아키노드 #N」, 「실행#N」, 이름 없는 창 포함).
2. 각 세션의 마지막 대화 6~12개를 `list_events`로 읽는다.
3. 세션마다 셋을 뽑는다 — **끝낸 것**(커밋 해시) / **안 끝난 것** / **한울님이 해야 할 것으로 남긴 것**.
4. **세션 보고를 그대로 믿지 않는다.** "배포 완료"라고 써 있어도 3단계에서 실측.

## 3단계 · 실측 대조

| 확인할 것 | 방법 |
|---|---|
| 로컬 = 원격 | `git rev-list --left-right --count origin/main...main` → `0 0` |
| 로컬 = 라이브 | 오늘 커밋에서 바뀐 html/js/css 중 대표 3개를 `curl -s https://archinodekr.com/<경로>`로 받아 로컬 파일과 해시 대조 (`tools/deploy.ps1`이 같은 일을 한다). GitHub Pages는 5~10분 걸리므로 방금 push했으면 기다린다 |
| 보안 규칙 | `git log --since=midnight --name-only -- firestore.rules`에 커밋이 있으면 **콘솔 게시가 됐는지** 한울님께 여쭙는다. 우리가 확인할 방법이 없다 — 「게시하셨습니까?」를 보고에 명시 |
| 메일 | 오늘 폼·메일 문안을 고쳤으면 Extension 설치 여부가 확인됐는지(작업일지 A-③) |

**⚠️ 라이브와 로컬이 다르면 그 자체가 오늘의 최우선 보고 항목이다.**

## 4단계 · 위험 신호 점검

1. **push됐는데 node-black 검수를 안 거친 코드가 있나?** — 최우선 보고.
2. **미푸시 커밋이 있나?**
3. **다른 세션이 만들다 만 미커밋 수정이 워킹트리에 남아 있나?** — 다음 push에 동승하지 않게 표시.
4. **큰 파일(`magazine.html`·`lang.js`·두 dashboard)을 Edit 도구로 통째 치환한 흔적이 있나?** — 끝부분 잘림 확인(`tail -5`로 `</html>`이 있는지).
5. **`firestore.rules`를 고쳤는데 콘솔 게시 확인이 없나?**
6. **보류 영역(작업일지 B·C)을 건드린 작업이 있었나?** — 건드렸으면 그 자체가 보고 대상.
7. **테스트 데이터를 지운 작업이 있었나?** — 지우지 않기로 했다(규정집 1-12). 만든 것은 목록으로 남았나.
8. **작업일지가 마지막 커밋보다 오래됐나?** — 종료를 못 밟은 날이 있다는 뜻. 그 날들도 5단계에서 같이 메운다.
9. **"다음에 할 일"에 이미 끝난 항목이 남아 있나?** — 커밋 로그와 대조해 걷어낸다.
10. **검수 대장에 올리지 않고 보고서 md에만 적힌 결함이 있나?** — 대장으로 옮긴다.
11. **정책 숫자(요금·날짜·계정 목록)를 코드에 새로 박은 곳이 있나?** — 규정집과 어긋나면 규정집을 먼저 고친다.
12. **자격정보(비밀번호·API 키)가 문서·대화에 평문으로 적힌 곳이 생겼나?**

## 5단계 · 기록 남기기

- `docs/작업일지.md` 맨 위 "다음에 할 일"을 오늘 상태로 갱신하고, "이력"에 오늘 덩어리를 추가한다(끝낸 것·안 끝난 것·만든 파일·커밋·못 본 것).
- 결정이 바뀐 날이면 `docs/ARCHINODE 규정집.md` 판 번호를 올리고 「이번 판에서 달라진 것」과 4부 연표에 적는다. 코드만 고친 날은 날짜만.
- 오늘 고친 결함은 어드민 검수관리 탭(못 하면 `docs/검수대장.md`)에서 `확인대기`로, 브론즈가 재확인한 것은 `확인완료`로.
- 브론즈 마라톤이 돌았으면 `docs/브론즈-진행상황/YYYY-MM-DD.md`가 마지막 라운드까지 적혀 있는지, 만든 테스트 데이터 목록이 작업일지 이력에 옮겨졌는지.
- 한울님이 부재 중이었으면 작업일지 맨 위에 **「A-0. 복귀 시 먼저」** 절(결정 요청·한울님 손 필요한 것)을 두고, 복귀 보고 첫 줄은 「그동안 이렇게 했습니다 + 종료할까요?」.
- 전부 커밋하고 **push까지**(`tools/deploy.ps1`, 문서만이면 `git push` 뒤 `-NoPush` 대조).

## 5-1단계 · 에이전트·스킬 업그레이드 제안 (제안만 — 승인 후 반영)

오늘(이 세션 + 2단계에서 읽은 세션들)에서 둘을 찾는다:
1. **정정 패턴** — "확인했다고 했는데 틀렸다" 같은 일.
2. **한 번 쓰고 사라질 뻔한 노하우** — 즉석에서 설계해 썼는데 정식 파일 어디에도 없는 것.

찾았으면 대상 셋(`.claude/agents/*.md` · `.claude/skills/*/SKILL.md` · 루트 `CLAUDE.md`)에 **무엇을 추가할지 문장으로** 제안하고, 각 파일의 현재 줄 수(`wc -l`)를 같이 적는다. 에이전트·스킬은 500줄, **CLAUDE.md는 150줄 넘으면 위험 신호**. 이미 길면 추가와 가지치기를 한 세트로. 이 항목은 6단계 보고에 섞지 않고 **별도의 짧은 승인 목록**으로 낸다.

## 6단계 · 최종 보고

1. **오늘 끝난 것** — 결과 중심, 커밋 해시 괄호.
2. **안 끝난 것** — 무엇이 왜 멈췄는지.
3. **위험 신호**(4단계) — 없으면 "없음"이라고 명시.
4. **한울님이 해야 할 것** — 콘솔 게시·Extension·비밀번호처럼 이게 있어야 진도가 나가는 것.
5. **다음 첫 작업** — "여기서부터" 한 줄.

보고에서 하지 말 것: 못 본 것을 본 것처럼 쓰기, 화면 위치로 지목하기, 창끼리의 기술 이야기 중계.

## ★ 종료를 못 밟고 끝나는 경우

가장 큰 구멍은 **"종료"라고 말할 기회 없이 창이 닫히는 것**이다. 대비는 두 겹:
- **시작 쪽** — `archinode` 스킬 1-3의 두 날짜 대조(마지막 커밋 vs 작업일지 갱신일)가 밀린 날을 잡아낸다.
- **종료 쪽** — 5단계에서 **작업일지 마지막 갱신일부터 오늘까지**를 확인하고 밀린 날도 함께 메운다.
- 밀린 날이 있었던 날에는 6단계 끝에 「하루를 마칠 때 "종료" 한마디면 이 절차가 돕니다」를 한 줄 덧붙인다. 강요하지 않는다.

## 이 절차를 고치는 규칙

종료 중에 새로운 유형의 사고를 발견하면 4단계 목록에 한 줄 추가한다. 날짜와 이유를 남긴다.
